# 部署自己的飞书 Codex Agent

使用随附的 [完整部署指南](references/FEISHU_CODEX_DEPLOY.md) 和 [源码包](assets/clawbot-feishu-deploy-20261113.tar.gz)。指南与程序都需要；技能文本本身不是桥接服务。

## 先确认部署目标

- 目标实现经过 Linux 验证，需要 Python 3.10+、tmux、Codex CLI 和自己的飞书自建应用。Mac 可准备材料或通过 SSH 执行，不把 Linux 验收等同于 macOS 验收。
- 新用户使用自己的 Codex 登录、飞书 App ID/Secret、绑定、状态目录。不能复制原用户账号、已有会话数据库或 App Secret。
- 已有运行中的实例先做只读检查。用户只要指南、安装个人配置或查看状态时，不启动服务、不配置凭据、不发送消息。

## 实施顺序

1. 读取完整指南，确定目标 Linux 用户、源码位置、默认项目及私有状态目录。
2. 将附件传到该服务器，用 `tar -xzf` 解压到新的程序目录；进入 `clawbot-feishu/`，运行 `sha256sum -c SHA256SUMS` 核对原包内容。
3. 显式设置四个变量：`CODEX_HOME`、`CODEX_BRIDGE_PROJECT`、`CODEX_FEISHU_STATE`、`CODEX_BRIDGE_BIN`。源码保留旧路径默认值，不能省略环境覆盖。
4. 安装依赖，在所选 Codex Home 登录并完成一次非 ephemeral 的最小对话，确认会话索引已经创建。
5. 按指南创建并发布自己的飞书应用。消息事件与卡片回调分别配置长连接；仅机器人 Webhook 不足以做双向交互。
6. 在目标机隐藏输入 App Secret，手机使用一次性口令绑定。凭据不得进入聊天、Git、命令参数或验收报告。
7. 检查服务进程、最新连接 health、真实消息回复、按钮与上下文续接，区分这几层证据。未经真实手机往返验证，不声称部署全部成功。

## 原实现需要保留的约定

- 新建飞书会话默认 Full access，具有启动它的系统用户权限；默认项目目录不是访问沙箱。部署者可自行选择更受限模式，管理员限制始终有效。
- 同一状态目录只允许一个活跃消费者；同一 Linux 用户下的管理脚本使用固定 tmux 会话名，多个用户应隔离部署。
- 只接收已绑定用户的私聊。停止当前回复不等于停止独立训练；解锁 app-server 可能断开桌面会话，不能当作连通性测试。
- 文字与图片不依赖 GPU；语音转写是可选组件，需要额外环境和本地权重。
- 主动通知只在用户授权的任务范围内发送，按事件去重，只报关键结果或故障。

## 维护与兼容性

程序快照日期为 2026-11-13。它读取本地 Codex 状态并使用 app-server 接口，目标客户端升级后需检查握手、模型列表、权限和线程接口。不要为兼容问题清空用户历史或自动放宽绑定。

在隔离的源码副本运行指南中的模拟测试；运行测试不应调用真实飞书 API。平台配置与手机登录等步骤只有部署者能完成时，明确告知剩余步骤。
