# Clawbot：飞书与微信 Codex 机器人

> 跨机器使用：文中的 `/aigc`、`/proc`、GPU 和集群操作属于原 Linux 服务器环境；在 Mac 上先确认远程目标与路径。历史参数和操作授权不是当前任务的默认授权。


将两个聊天入口作为同一套系统维护：共享 Codex 会话目录和任务引擎，各自保留绑定、会话选择、队列及展示方式。本技能依据 2026-10-19 的实际源码整理；修改前核对当前实现，不把旧会话里的界面要求或测试回执当成当前事实。

## 按任务读取

- 新建应用、首次绑定、重建环境或恢复服务：读 [创建与部署](references/setup.md)。已有绑定优先复用，不为了查看配置执行重新绑定。
- 调整飞书卡片、历史、模型/权限或微信口令、语音、图片：读 [布局与功能](references/interface.md)。该文件记录实际交互约定及两端差异。
- 改代码、查队列/锁、停止任务、升级重启或验证：读 [架构与维护](references/maintenance.md)。
- 只要求总结或编写技能时，读取源码并写文档即可；不启动、停止、解锁或重绑正在使用的机器人。

只保留一个微信、一个飞书；微信启动器和 Python 入口都会拒绝额外实例。两端只接收各自已绑定用户的私聊，不因新功能放开群聊、其他用户或任意收件人。

技能不包含机器人程序、凭据、队列数据库或模型权重。恢复依赖表中的共享数据仍在；若缺失，明确缺的是源码、绑定还是历史，不能以新建空会话代替找回原上下文。整机迁移还需要现有 `houyi-workspace-migration` 技能及共享 `vscode_h200/` 启动脚本；本技能只负责机器人部分。

## 保留的产品行为

1. **飞书使用原生卡片。** 保留“会话操作”和“会话设置”分组、稳定 thread ID 按钮、红色停止/解锁按钮、角色分色的历史分页；模型列表只列模型，推理强度是单独入口。具体行列布局见参考，不根据旧记忆重排当前卡片。
2. **飞书新建会话默认 Full access。** 对新草稿使用 `danger-full-access`、`approvalPolicy=never`，同时尊重管理员限制；不把免审批扩大到全部历史会话或微信。手动切换现有会话到完全访问，保留当前卡片的确认提示。
3. **标题来自真实主题。** 新建飞书会话首条用户消息用于命名；长标题可缩略，不能用“飞书新会话”覆盖已有主题。“当前”只显示主题、目录、状态、操作提示和已知的最近运行模型/强度。
4. **两端使用原生 Codex 线程。** 未占用历史按原 ID 续聊；占用时只读历史或明确分支。查看历史不执行 `thread/resume`，不扫描其他用户的 Home。模型/提供商按当前账号能力校验，不能把账号不兼容误判为消息通道断连。
5. **停止与解锁不同。** 停止只中断该桥接发起的当前 turn，需防迟到回调误停新任务；全局解锁会断开同 Home 的 Codex app-server，可能中断当前聊天，只有用户明确要求解锁时才执行。二者都不能当作已停止独立训练进程。
6. **微信保留当前通道能力。** 文字口令、手机排版、语音理解、向绑定用户发图可用；不能把飞书卡片直接套到 iLink，不能承诺个人好友列表、任意好友发送、语音回复或尚未实现的入站附件。

## 工作与交付

先按请求定位源码和私有状态，检查运行环境、所选会话及相关任务。修改共用引擎、持久化或锁逻辑时同时考虑两个入口；只改布局时保持绑定、原会话和历史不变。配置秘密只在本机私有文件/隐藏输入中处理，避免写入聊天、命令行参数、技能或 Git。

按变更选择现有模拟测试和隔离卡片预览；新功能需要真实平台验证时，只在用户已授权的测试范围内发送消息。若本次只获准写技能，不发送试验消息，不实际执行审批、停止、解锁或重启。

交付实际修改的文件、验证结果和仍需平台/手机操作的步骤。区分“进程存在”“通道连接”“队列正常”“模型回合完成”“手机收到回复”；不把旧 health、tmux 会话存在或模拟测试通过当成真实消息已送达。
