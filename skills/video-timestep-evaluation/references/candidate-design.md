# Candidate schedule design

Use this reference after the user provides a sampler, timestep transform/shift, a total number of sampling points, and either an explicit high/low boundary or enough scheduler context to identify one.

## Coordinate space

Design distributions in the scheduler's meaningful/raw coordinate space when possible. Convert the resulting values with the model's declared transform once, then submit and display the converted list. Do not average already shifted values when a raw-space midpoint is intended.

For a commonly used flow shift `s` and raw normalized sigma `u`, one possible mapping is:

```text
shifted_t = 1000 * s * u / (1 + (s - 1) * u)
```

This is only an example. Obtain the actual transform from the sampler/reference implementation; some models use a different transform or no shift.

## Original-sampling baseline

Generate the original baseline from the model's native sampler schedule, not from a custom candidate. Classify each resulting value by the agreed high/low boundary.

- If its actual split equals one requested group, use it as that group's C1 and label it `原始采样`.
- If it yields another split, preserve it as a standalone `原始采样N步` baseline. Do not relabel it to fit a convenient requested group.

Example: if the boundary is 973.0 and a native 16-point list contains five values above it and eleven at or below it, it is a 5+11 baseline even when the experiment tests only 4+12, 6+10, 8+8, 10+6, and 12+4 candidates.

## Building a candidate set

For each requested `H+L` group, return the requested number of candidates and enforce:

```text
len(list) == H + L
strictly descending values
high segment: values above the agreed boundary
low segment: values at or below the agreed boundary
same start/end policy as the reference sampler
```

Avoid returning only subsequences of a previous list. Build diversity deliberately across candidates:

1. **Balanced spacing:** distribute points across each segment in raw/scheduler space.
2. **Early-high density:** concentrate more high points near initial noise while retaining a bridge toward the boundary.
3. **Transition density:** add points around both sides of the high/low boundary.
4. **Low-tail emphasis:** preserve or densify late denoising intervals where motion/detail changes may appear.
5. **Mixed midpoint schedule:** insert raw-space midpoints between useful anchors and move a subset of low points, rather than merely deleting points.

Anchor candidates to known-good schedules when available, but keep candidates meaningfully different. Retain the same terminal policy (for example, an explicit final timestep followed by the sampler's terminal sigma) as the reference implementation.

## Presenting candidates

Use one decimal place unless the reference sampler requires more. Show the split separator (`|`) in proposals, then serialize the same values as a comma-separated list for execution. Include a brief rationale for how C1–C5 differ; never imply that a candidate is model-optimal before it is evaluated.

When candidates were generated by the skill rather than supplied by the user, obtain explicit confirmation that the candidate set is acceptable before preparing the execution preflight summary. Candidate acceptance alone is not authorization to start GPU work.
