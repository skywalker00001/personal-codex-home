# Video Timestep Evaluation：极简使用方式

使用者只需提供四项：

1. **模型权重路径**；
2. **可参考的推理脚本入口**；
3. **想测的步数组合**，以及已有候选（若有）；
4. **可用 GPU 节点/卡**（只给节点也可以）。

直接复制：

```text
使用 video-timestep-evaluation。

模型权重：<checkpoint 路径>
参考推理脚本：<inference.py 路径>
测试组合：例如 4+12、6+10、8+8
候选：<已有 list；没有则写“请先给候选”>
可用 GPU：<节点和卡号>
```

## Skill 默认行为

- 未给候选：先检查参考推理脚本和权重配置，给出候选和原始采样 baseline；先确认候选可行，再列完整需求并等待“确认启动”。
- 已给候选：检查 timestep 语义后，仍会列完整需求并等待“确认启动”。
- 默认快速验证 prompt：长期 16 prompt CSV 中的 `t2v_007`（揉面团）和 `t2v_011`（芦苇荡）。
- 只给节点时：先找出其空闲卡并列入确认单；确认后每张卡一个常驻 worker，绝不默认退化成单卡。
- 默认持续监控到完成、上传 MMS、产出 URL CSV，并建立一个新的展示网页；所有展示页会复用同一个公网 URL 前缀/服务，只以不同 HTML 名称区分，不会为每个实验重复申请 Cloudflare 站点。网页创建后会验证具体页面链接并将其告知使用者，整个推理期间保持可访问。需要扩展到完整 16 条 prompt 时再说明。
- 生成、MMS 上传、网页更新三者逐任务并行：推理开始前网页已列出完整任务矩阵的等待卡片；每项依次显示等待/推理中/上传中/已发布（或失败）。任一视频生成完立即上传，URL 验证后立即显示；网页以无缓存轮询自动更新，其余卡继续推理，无需等待其他任务或手动刷新页面。
- 已经 shift 的 timestep list 不会二次 shift。
- 无论候选是否已给出，Skill 都会在占用 GPU 前列清模型、实际 list、prompt、GPU、参数、run root、交付物，以及展示页共用公网前缀、具体页面 URL/服务方式，等待明确“确认启动”后才拉起任务。
- 用户尚未给出“已选候选”时，展示页会默认全选、展示所有候选组和全部 C 候选；仅“只看已选候选”和同一行的候选组总开关不可用（总开关保持全选显示）。下方完整候选组里的子组开关与 C1–Cx 必须可操作；“清空 / 默认 / 全选”保持模板原有行为。只有用户给出已选候选后，才启用并默认选中。
- 使用者给出“已选候选”后，会在同一展示页更新状态并重新验证：顶层开关解除禁用、筛选和全部候选控制均可正常点击，不会留下失效的禁用样式或事件。
- 扩展到完整 16 条 prompt 时：会复用参数完全一致且已有成功 MMS URL 的结果，只推缺失项；默认只交付按源 CSV 顺序的 URL CSV，不更新展示网页。若需要更新网页，请额外明确说明。
- 展示页不是重新设计：会直接复制 `index_5-3_1200.html` 作为模板，只替换数据和运行连接；在返回公网链接前会按模板逐项验收布局、筛选区、四色语义、四列视频卡片、播放/暂停及实时更新。

除非有特殊需求，无需预先提供 CFG、VAE、基模、seed、输出目录或网页名称；Skill 会从参考实现中检查并采用安全的新 run 目录。若这些参数不能从参考代码确定，Skill 会说明发现的缺口后再继续。
